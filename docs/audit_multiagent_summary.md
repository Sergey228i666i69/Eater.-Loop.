# Сводка Мультиагентного Аудита

Дата: 2026-05-14.

Формат: пять read-only агентов проверили независимые срезы проекта: архитектуру и состояние, gameplay loop, интерактивы, tooling/assets/tests, repo hygiene. Исходный код аудиторы не меняли. Один tooling-агент запускал проверки и зафиксировал: parser-only проходит, полный runtime suite падает. Финальный прогон после создания документации подтвердил красный suite с 1 failure по directional contract старого прожектора.

## Вердикт

Общая проблемность: **7.3/10**.

Репозиторий не выглядит "безнадёжным клубком": у него понятная Godot-структура, есть autoload-контуры, уже заведены тесты и часть систем оформлена лучше среднего прототипа. Но костыльность высокая и уже не только эстетическая. Несколько проблем прямо влияют на игру: прогресс может блокироваться, чекпоинты теряют динамические угрозы/состояние, run может остаться активным после концовки, часть input-контрактов сейчас расходится с `project.godot`.

| Срез | Оценка проблемности | Главный диагноз |
| --- | ---: | --- |
| Архитектура и состояние | 6.5/10 | singleton-и, строковые пути, публичный mutable state |

## Самые Важные P1

1. **Fresh clone почти наверняка не воспроизводит игру.** `.gitignore` исключает почти все asset-like файлы и `export_presets.cfg`, но сцены используют сотни локальных `res://` ссылок.
2. **Полный suite красный.** Финально воспроизводится directional contract старого прожектора; tooling-агент ранее также видел bedroom ambient suppression failure, который не повторился в финальном прогоне.
3. **`lamp_switch` отсутствует в Input Map.** При этом старые `lamp.gd` и `projector.gd` всё ещё возвращают это действие.
4. **Sleep/wake sequencing сломан.** `Bed` ставит pending sleep spawn, но `GameState.next_cycle()` сбрасывает `CycleState` до следующей сцены.
5. **Run не закрывается после концовки.** Credits возвращают в меню без `GameState.reset_run()`, а Continue может остаться активным.
6. **Динамические враги не восстанавливаются чекпоинтом.** Snapshot path-based; если ноды нет в свежей сцене, она пропускается.
7. **Потолочный враг фактически игнорирует лампы.** Проверка `is_point_lit` недостижима из-за `continue`.
8. **Dependency-система интерактивов может запереть прогресс.** Дверь может не вызвать complete-state, а завязанные объекты ждут именно его.
9. **Нет единого выбранного интерактива.** Все `InteractiveObject` слушают input сами.

## Что Стоит Сохранить

- Локальный тестовый слой уже есть, и он не чисто декоративный.
- `MusicManager` имеет публичный фасад и тест на запрет приватного API.
- `MinigameSettings` как `Resource` - правильное направление.
- `InteractiveObject` - хорошая база для будущего централизованного `InteractionManager`.
- В проекте уже есть документация по отдельным системам, её можно расширять, а не начинать с нуля.
